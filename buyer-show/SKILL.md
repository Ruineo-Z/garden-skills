# Buyer Show · 买家秀生成

根据商品参考图，编写或生成具有多样性的买家秀。主动设计有区别的人物姿势、商品使用状态与拍摄方案；商品正确、拍摄可行和普通手机质感是方案成立的边界。

## 范围与执行边界

- **默认一份，明确数量时生成对应数量的独立方案**。例如“生成三张”直接按三张执行，“写三份提示词”交付三份完整文本，不询问是否改成一份，不静默减少数量。每份分别推导拍摄方案、组装 prompt；只有出图模式调用图像工具，不新增复杂批量管理。
- **不支持同人物一致性成组**。只有用户明确要求“同一个人 / 同一模特 / 保持人物一致”等时才说明边界，并确认是否接受多张独立图片；“一组 / 三张买家秀”本身不等于人物一致性要求。
- 覆盖配饰：帽子、眼镜、首饰、围巾、包、腰带等；不支持服装与鞋类。
- 买家视角：普通人在日常生活中记录佩戴 / 使用效果，可以短暂停下来调整姿势拍照。默认沿用她当时的日常衣着与妆发，不因拍买家秀而升级为礼服、精致妆容或专门布置的拍摄场合；照片可以清楚好看，仍采用现场光与普通手机拍摄。
- 商品保真通过参考输入与生成约束尽量维持，不代表输出已验证与实物一致。
- **不做生成后自动看图审核，也不因视觉质量自动重试**。生成后直接交付；只有用户反馈问题或要求重出时才返工。

## 交付模式

根据用户话术决定，不例行询问模式：

| 用户要求 | 执行范围 |
|---|---|
| “写 prompt / 提示词”“先别出图”“只要提示词” | 完成方案与完整 prompt，保存并交付，到此结束；不调用图像工具 |
| “先给我看方案 / 提示词”“确认后再生成” | 交付简短方案与完整 prompt，等待用户确认；确认前不调用图像工具 |
| “生成买家秀 / 图片”“出图”，或未要求停在提示词阶段 | 组装完整 prompt 后直接生成，不额外要求批准 |

明确的“只要提示词 / 先别出图 / 等确认”优先于泛指“生成”的表述。“提示词并出图”按直接出图执行，并交付提示词。预览获确认后沿用已确认方案和 prompt，只修改用户反馈的部分，不重新随机选择人物、场景或拍法。

## 前置判断与提问

商品图是唯一硬必填项。先确认目标可辨认、关键结构可见，多商品图能指认目标。缺图、关键细节被遮住或目标不明时，索取补充信息；得到可用信息后继续，不额外要求第二次确认。水印不遮住关键商品信息时，不单独判为不可用。

**实际出图必须支持图像参考输入**：把商品图实际传入图生图 / 图像编辑工具。出图模式遇到只有文生图或没有图像工具时，改交付完整 prompt，明确注明未生成图片。仅提示词或预览模式不依赖图像工具可用性，但仍须依据商品图编写，并说明执行该 prompt 需要支持图像参考输入的工具。

除用户提出的要求外，只在以下情况提问：

| 情况 | 处理 |
|---|---|
| 明确要求同人物一致性成组 | 说明当前不支持人物一致性，确认是否接受独立图片 |
| 要多张图片或多份提示词但未给数量，如“来几份 / 一组” | 只询问数量；已给数量或授权自行决定时不再确认 |
| 缺商品图、图不可用或多商品目标不明 | 索取可用图或确认目标 |
| 品类影响穿戴判断且把握不足 | 确认品类，不靠猜；优先采信用户给出的品类名 |
| 缺尺寸依据，影响戴法可行性或用户要求的展示比例 | 询问尺寸或上身参考；处理见步骤 ① |
| 用户对真实程度的说法相互矛盾或含义不明 | 只澄清是否接受统一的真实买家秀质感；不另设质感选项 |

所有请求默认采用统一的**真实买家秀质感**，不提问选择精致度。人物有可见面部时，明确采用素颜或简单日常淡妆与自然皮肤状态；每份 prompt 均写入轻微但可见的白平衡偏差和细微噪点，不只在暗部几乎不可察觉。商品应可辨认，不追求全画面均匀锐利、材质纤毫毕现的商业精修效果。具体人物与成像要求见 `references/realism-library.md`。

## 单份执行单元与数量处理

一份方案及其 prompt 是核心执行单元：

```text
交付模式 + 前置判断
  ↓
① 商品属性与可用变化   → 商品条件
② 完整拍摄方案与多样性 → 有区别的拍摄方案
③ 成立性检查与组装     → 完整 prompt 文本
④ 按模式交付          → 仅提示词 / 待确认 / 执行一次生成，保存记录
```

多份独立请求先确定数量。同商品的商品解读与已确认尺寸共享，不重复询问；每份分别执行 ②–④，不为每份另加确认。出图模式共享工具能力判断并逐张生成，不等待看图审核再生成下一张；提示词 / 预览模式按数量交付文本，不调用图像工具。当前请求已采用的方案即为后续方案的差异化参考。每张实际生成仍传入商品原图，不把上一张生成结果当成人物一致性参考。

内部推导不需要逐步展示或逐项向用户确认。读取 `references/prompt-patterns.md`、统一真实质感规范及对应部位文件即可；其他部位按需读取。

### ① 商品属性与可用变化

1. **目标与品类**：指认参考图中的目标，判断品类。不明确且影响穿戴判断时先询问。
2. **商品本身与使用状态**：商品原有材质、裁剪、部件、连接关系与固有尺寸需要保留；戴法、朝向、折叠、受力与垂坠可以随合理使用变化。不把参考图的摆放轮廓当作固定形状。柔性物品可产生符合材质的弯曲、交叉、褶皱与展开，不能因此改变裁剪、增加部件或不合理伸长；刚性部件仍须保持原有形态。
3. **尺寸依据**：具体数值只采用用户提供的尺寸或商品图中清楚可读的标注。上身参考可支持戴法与相对比例判断；普通商品图的相对比例只用于保守判断，不换算成厘米数，不据此指定精确落点。缺依据且影响戴法或用户要求的展示比例时，询问尺寸或上身参考。用户补不了，保留未知项并选择不依赖该尺寸的可行方式；仍无法判断时补问关键依据。贴合型通常无需询问，明显的适配疑点除外。
4. **可用变化**：依据实际固定机制、身体部位、材质与尺寸，判断哪些佩戴 / 携带 / 放置方式及形态变化可行。未知带长不能默认上肩或斜挎，不让模型改造商品来扩大方案范围。没有精确比例依据时不承诺与实物大小一致。

只读取目标部位文件：头部 → `references/parts/head.md`、面部 → `references/parts/face.md`、颈部 → `references/parts/neck.md`、手部·腕部 → `references/parts/hand.md`、腰部 → `references/parts/waist.md`、肩背 → `references/parts/shoulder.md`、脚部 → `references/parts/feet.md`。文件缺失时按上述商品条件推导，并告知使用了兜底方案。

**商品条件**简要记录目标、品类 / 部位、尺寸依据或未知、需保留的属性、可行使用变化及明确的人群定位。不同方案共享商品条件，不建立复杂档案。

### ② 完整拍摄方案与多样性

**从普通人在当前情境下常用的拍摄方式，推导整张照片。**结合商品条件、本张想记录的佩戴 / 搭配效果、人物所处的场景与照片类型，共同设计人物姿势、机位、取景和商品呈现。选择依据是普通人在同类情境中通常会怎样拍，而不只是手臂能够到哪里、镜头能看到多少商品表面；商品随整张照片自然呈现，不为拍全正面、轮廓或图案另造拍法。用户明确要求外观或细节展示时，仍从该情境下常用的拍摄方式设计。用户未指定的条件可在合理范围内形成不同方案，不逐项随机拼接互不相容的条件。

**默认场景是普通日常环境，装修、设施与陈设也保持普通日常水平。**先确定她当天所处的生活情境与环境，再确定衣着、妆发、使用状态和拍照方式。场景可以整洁、好看，有自然的美感；选择依据是普通人在日常生活中常见的环境，而不是空间的装修档次、装饰是否讲究或整体风格是否协调。地点名称属于日常场所并不足够，仍须判断具体环境是否过于精致；不主动选择或补出装修考究、陈设讲究、氛围经过精心设计的空间。不根据商品的光泽、五金、镶钻或价格感升级场景，高档社交场所、晚宴、礼服或精致布置只在用户明确指定时采用。照明沿用该地点正常使用的条件，可以为了看清佩戴效果做简单调整。具体环境与照明表达见 `references/realism-library.md`。

**写提示词前，先形成能明确描述的完整姿势。**记录佩戴或搭配效果本身就可以成为摆拍理由，不要求每个动作另有生活用途。结合人物情境与取景，确定可见的身体朝向、脸部朝向与视线、主要手臂动作，以及影响姿态的腿部、重心或支撑关系；这些选择须相互配合，涉及环境支撑时明确人物与支撑物的接触。只确定影响当前画面的部位，不为每张安排所有关节，也不补画面外的动作。不能停在站着、坐着或姿势放松，也不能只确定一只手怎样展示商品、把整体姿势留给生图模型补全。

**商品状态与完整姿势一起确定。**明确商品在该姿势下相对身体的位置、接触与支撑，以及动作产生的受力、折叠或垂坠；手部参与时确定手的位置和商品最终状态，不只写动作意图或幅度修饰。手臂可以参与整体姿态，不要求每张直接操作商品，也不默认以提向镜头、摆正展示面或拉开图案来表现商品。动作范围由佩戴方式、材质与本张需要记录的信息共同决定；覆盖身体较多、具有柔性或多种穿戴方式的商品，可表现不同使用状态，小型配饰更多利用相关身体部位的朝向、姿态与取景。按本次条件推导，不使用固定模特、动作组合或按序轮换的姿势清单。

**将共同设计的拍摄关系说清楚，再检查能否成立。**确定谁持机、镜头位置与方向、必要时使用前置还是后置镜头，以及该镜头中可见的身体、商品和环境；使用镜面时按实际反射判断。检查持机占用、人物动作与自拍时看屏幕的需要是否相容。可操作只说明方案能够完成，不能代替它是否符合日常拍摄习惯的判断；不先寻找最能展示商品的角度，再给人物安排动作来配合。组装时沿用已选方案，照片类型和成片内容的具体表达按 `references/prompt-patterns.md` 执行。

对应部位文件中的拍摄指引用于判断该部位在日常生活中通常怎样被拍到。结合部位相对视线的位置、人物正常站坐姿和持机习惯选择角度；下面的拍法关系只是成立条件，不代表每一种拍法都适合每一个部位，也不要求多张覆盖全部拍法。

局部图保留商品与相邻身体关系，整体搭配或垂坠图再扩大范围；不要求每张同时拍清人物、全部商品细节和整体搭配。商品可以随正常使用呈现侧面、折叠或少量遮挡，只要本张要记录的信息仍可辨认。姿势与机位相互调整，不能为了可见性改造商品；双手被动作占用时选择帮拍，不新增支架或定时拍摄流程。

| 拍法 | 拍摄关系 |
|---|---|
| 伸臂自拍 | 本人单手持机，约一臂距离，朝向目标部位；适合实际距离能够覆盖的近景，不硬塞全身范围 |
| 对镜自拍 | 人物在可用镜子前，手机朝向镜面；镜中手机位置与商品可见范围相容 |
| 本人俯拍局部 | 相机位于目标上方朝下，取景服从实际相机位置，而非外部正面视角 |
| 请人帮拍 | 另一人持机，距离、高度与方向配合本张动作和局部 / 半身 / 全身取景 |

镜面会反转商品左右关系和文字。目标有文字 / logo 或明显不对称时优先非镜面方式；用户坚持镜面时说明风险，交付时提醒核对，不自动看图检查。

**人物与环境**服从用户要求、商品人群和本张日常情境。未指定时默认女性，明确男性定位才选男性，不仅凭颜色或材质判断。带脸时选择少量可见外貌特征，明确素颜或简单日常淡妆，保留自然皮肤纹理、轻微肤色不均及随人物变化的少量瑕疵；妆发与表情按生活状态确定，不为了商品统一整理成精致仪态。面部不入镜时只写可见皮肤、衣袖与身体关系，不补完整人物设定。场景写明具体地点与现场光，并根据该地点平时如何被使用、拍照时周围正在发生什么，确定镜头内具体的环境状态；按 `references/realism-library.md` 将使用情况落实到可见对象、位置与状态，而不是仅写一个背景名称。

**多张要比较完整方案。**参考本次请求、当前对话与可取得的最近相关方案，在商品与取景允许时优先选择尚未采用的姿势与拍摄关系。比较实际可见的身体朝向、手臂与支撑关系、人与商品的关系及画面呈现；只换衣服、背景、脸型或从站姿换成坐姿，不能作为姿势差异的充分依据。若可见姿势与关系仍相似，重新设计方案，而不是只改措辞。差异可以来自完整姿态、商品使用状态或与姿势配合的取景，不要求每张更换戴法或增加操作商品的手部动作。多样性在同类情境常用的拍摄方式中展开；动作空间有限时，利用相关部位姿态、朝向与取景形成区别，不为增加差异采用少见的拍法或强加大幅动作。

用户指定或要求保持的条件优先，返工只修正反馈部分，不强制差异化。比较只使用当前可取得的方案，不要求扫描全部历史、创建去重系统或审核生成图片；缺历史时正常推导，不承诺跨会话永久不重复或同人物一致性。

**拍摄方案**简要记录拍照意图、人物与场景、商品使用状态、具体姿势、拍法与取景。多份只需在已有方案中确认区别，不另建人物档案。

### ③ 成立性检查与组装

生成前先核对整张方案是否符合普通人在同类情境中的常用拍法，而不是只因商品更可见或机位可操作就采用；再检查可见姿势、支撑与环境是否相容，商品本身是否保留原有结构、使用形态是否符合材质，以及相机位置、朝向、持机占用和实际可见范围是否一致。最终文本的照片类型与已选拍法对应，画面内容来自同一拍摄镜头。发现冲突时调整完整方案，关系含糊时补清必要信息，不靠叠加禁止项解决。

按 `references/prompt-patterns.md` 组装完整、可复制的 prompt，写明已选方案的可见关系，每项信息表达一次；省略推导过程、备选项与画面外细节。现场光和手机成像按 `references/realism-library.md` 表达。完整文本不能只存在于生图调用的临时参数中；此处只检查方案与文本，不增加生成后的图片审核。

### ④ 按模式交付与记录

1. **仅提示词**：交付每份完整 prompt，注明“仅交付提示词，未调用生图”，保存记录后结束，不检查图像工具或偷偷出图。**先预览**：同时交付简短方案与完整 prompt，标为“等待确认”，确认前不生成；后续按已确认文本执行。
2. **直接出图或预览已确认**：对每张，将实际商品参考图与该张完整 prompt 传入工具，各执行一次单张生成。参考图命名与工具输入对应，不能只在文本里提到图片。
3. 直接交付实际生成的图片，附“请核对商品与实物是否一致，尤其文字、图案与比例”。不要声称已审核或已保证保真；多张按序号对应结果，不承诺同一人物。
4. 出图模式无图像参考能力时，按请求数量交付独立完整 prompt，说明均未出图。某张调用失败或未返回图片时，记录该张原因，不自动重试或补图；只要工具仍可用，继续其余计划，结束时说明实际成功数量与未生成项。工具不可用时保留剩余 prompt，不反复调用或假称已完成。
5. 有文件写入能力时，每份保存记录，第一节是最终 prompt 全文；已生成图片按下面的同目录规则保存，最小记录格式见组装规范。保存后确认文件存在、图片与记录的编号对应，不重新看图审核。不能落盘或图片无法获取时，提供实际结果位置和完整 prompt，明确说明保存未完成，不虚构文件路径。仅提示词 / 等待确认是正常交付状态，不当作生成失败，不创建占位图片。

## 同目录保存

**每张生成图片与对应完整 prompt 必须在同一目录，使用相同编号 / 文件名主干。**prompt 保存在 Markdown 记录的第一节，不额外强制生成重复的文本文件。用户指定输出目录时优先使用，否则按参考图标识归档。记录用于复现、返工与追加参考，不用于强制全历史去重：

```text
buyer-show-output/<参考图标识>/
├── 001.md       # 第一节为第 1 张的完整 prompt
├── 001.png      # 第 1 张生成图片，扩展名按实际格式
├── 002.md
└── 002.webp     # 示例：第 2 张实际返回 WebP
```

参考图标识可用文件名 slug + sha256 前 6 位；无法计算时用可区分的文件名 / 用户标识。它只是归档键，不是永久商品身份：同商品换图可能不同，多商品图需加目标简述。先选择不冲突的编号 / 标识，图片与记录成对使用，不覆盖旧图片或无关记录。仅提示词 / 预览时先保存记录；后续按该方案生成后，可补充原记录的实际 prompt、状态与图片路径，在同目录保存同编号图片，若编号已被其他结果占用则另选编号。

工具把图片存到其他目录时，**将实际生成文件复制到记录目录**，不只记录外部路径；保留原文件，不移动或删除。工具返回可下载链接时，下载原图到同目录。按实际编码使用扩展名，不把 JPEG / WebP 仅改名为 PNG，不为归档重生成或有损重编码。记录中的图片路径指向同目录副本，必要时另记来源；复制 / 下载失败时如实保留实际来源并说明归档未完成，不能把不存在的副本当成交付。未出图时只保存 prompt 记录并注明原因，不创建占位图片。

## 用户反馈后的返工

只有收到反馈或重出请求后使用下表；部位文件的破绽清单也只用于诊断。

| 反馈 | 定向调整 |
|---|---|
| 水印、尺寸标注或参考图边框被继承 | 补齐参考图隔离约束 |
| 商品细节不符 | 区分合理使用形变与商品本身被改造，检查取景与遮挡，必要时收近，不靠外观复述硬凑 |
| 带子被拉长、穿戴或比例不对 | 回到商品条件，补尺寸依据或改为已确认可行方式 |
| 手畸形、镜腿穿头、耳饰悬浮 | 根据对应部位诊断，调整动作与机位 |
| 场景不搭或空间明显错误 | 核对提示词与参考图是否冲突、关系是否明确及拍法是否可行；有问题则修正。均成立而输出仍违反要求时，记录为本次模型执行失败，可按用户要求重出，不据此增加普遍限制 |
| 太精致或太像专业宣传图 | 检查取景、布光、锐化、修饰与材质细节是否趋向商业展示，以及普通手机成像要求是否落实；先修正拍摄与成像设计，不只提高噪点强度或补过曝与杂物 |
| 人物不对 | 调整人物信息，保留合理的商品与拍摄条件 |

针对用户指定的问题图片各执行一次修订生成，不自动连续重出，也不把整批无关图片重做。收近后用户仍反馈商品细节不符时，如实说明当前方案无法保证，建议实拍或后期合成。
