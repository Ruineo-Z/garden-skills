# Prompt 组装规范

本文件只定义最终 prompt 的表达结构、生成约束与记录格式。商品和拍摄方案按 `../SKILL.md` 推导；这里不另选人物、场景或拍法。

## 结构与信息要求

按以下顺序组织自然语言，**固定信息顺序，不固定句型**。不要求逐字套模板或输出八行字段；每项决定只表达一次，避免重复信息相互覆盖。

| 段落 | 必需信息 |
|---|---|
| 1. 照片类型与取景 | 开头直接说明要生成哪一种照片，沿用已选拍法；补充本张必要的角度、距离与取景范围，具体表达见下节 |
| 2. 商品与适配限制 | 指认目标、公共约束；只加入影响使用或比例的尺寸 / 结构依据 |
| 3. 人物与情境 | 从上述镜头可见的日常衣着、妆发与皮肤状态、姿势及商品状态，必要的接触和支撑关系，以及具体地点和镜头内的环境使用状态 |
| 4. 真实买家秀质感 | 简短说明现场光与普通手机成像；每份均落实 `realism-library.md` 中轻微但可见的白平衡偏差、细微噪点及清晰度要求 |
| 尾行 | 用户要求的比例；未指定时默认 3:4 竖版，手机照片质感 |

**保留完整姿势、商品、拍法与取景所需的具体信息，每项只表达一次。**局部图省略画面外的年龄、脸部、发型、身份和腿部姿势；半身图不为填字段安排脚尖与膝盖。推导中已确定且影响画面的身体关系要写入最终文本，不压缩成宽泛的动作目的；最终文本只写已采用的结论，不逐项转录方案记录。

不设硬性字数上限，也不为缩短文本把必要关系替换成“姿势自然、真实空间”等空泛描述。最终文本不留占位符、备选项、“同上”或内部推导标题。

## 照片类型与画面内容

**开头定义最终照片，再描述照片中的内容。**用“生成一张……”直接说明已选照片类型，不只叙述人物正在做什么；照片类型沿用拍摄方案，组装时不重新选择。下表只将已成立的拍法转换为表达，不是可随机抽取或为多张依次分配的拍法清单：

| 已选拍法 | 开头明确的照片类型 |
|---|---|
| 伸臂自拍 | 手机自拍照，按方案补充前置镜头及必要取景 |
| 本人俯拍局部 | 本人用手机向下拍摄的局部照片，明确目标部位与俯视范围 |
| 对镜自拍 | 对镜自拍照，画面呈现手机镜头拍到的镜中人物 |
| 请人帮拍 | 由他人用手机拍摄的照片，按方案补充拍摄方向与取景 |

后续人物、商品与环境描述均服从上述照片类型和机位，只写该镜头能拍到的内容。普通自拍的观察位置就是本人手机镜头；“人物举着手机自拍”是拍摄过程，不能替代自拍成片的要求。画面外的持机与身体动作留在方案中，不转录为可见动作；对镜自拍则写清镜中实际可见的手机、人物与商品关系。他人帮拍从帮拍手机的镜头描述被拍摄者，不把帮拍者的持机动作也写成画面内容。

## 固定公共约束

每份 prompt 的商品段均包含以下内容；只替换目标指认与实际参考图标签：

```text
以 REFERENCE_0 中的目标商品为准，保持颜色、图案、商品文字 / logo、材质、五金及原有裁剪、部件与连接关系，不改款或臆造细节，不改变固有尺寸。按本次方案呈现佩戴 / 使用形态，允许符合材质和结构的自然形变，不照搬参考图的摆放轮廓。
不继承参考图的水印、尺寸标注、平台 logo、边框或促销贴纸，不添加广告排版、标语或 logo 墙。
```

“目标商品”必须在多商品图中替换为明确指认，如“左侧粉色那一顶帽子”。参考标签应与工具输入顺序 / 命名对应。

**不主动用文字重建商品外观**：外观以参考图为准；文字用于指认目标、说明穿戴方式及必要尺寸依据，不再描述花纹排布、刺绣内容或补全看不清的细节。这是降低描述与参考图竞争的默认策略，不宣称适用于所有模型的绝对规律。

## 条件约束

只在输入或方案触发时加入，不给每份 prompt 堆全部限制：

| 触发条件 | 写入什么 |
|---|---|
| 尺寸 / 结构限制影响戴法或比例 | 写入结论与依据，例如“短提手用于手拎”；数值仅采用用户提供的尺寸或商品图清楚可读的标注，相对比例不换算成厘米数，不指定未经确认的精确落点 |
| 提供相关上身参考图，计划作为第二张参考输入 | `REFERENCE_0` 用于商品外观；`REFERENCE_1` 仅用于尺寸、穿戴关系与人体比例，不复制其人物、服装、场景、风格或布光 |
| 选择对镜自拍 | 明确镜头朝向镜面、人物和手机的位置，按真实镜面反射呈现，不混用直拍视角 |

上身参考默认优先采用已有依据的穿戴方式。换成其他方式时重新判断尺寸是否支持；依据不足则不换，不机械照搬参考图拍摄距离。

仅提示词 / 预览模式按计划的参考职责组装，记录每张参考图的计划映射；计划用双参考时说明执行需要支持多图输入的工具，不检查当前宿主图像能力。实际出图时才确认工具能力：支持多图则按映射传入；只能传一张时保留商品原图，不能假称传入了第二张图。将可确认的尺寸 / 关系结论写入文本，移除未使用的 `REFERENCE_1` 并更新记录，关键依据无法传达时先澄清。已确认的双参考预览若不能按原映射执行，告知限制及必要调整，不静默换成另一套方案。

## 写法与衔接

- 人物按主说明选择，最终文本只写本张入镜所需的特征。带脸时明确已选的素颜或简单日常淡妆，以及自然皮肤纹理与轻微肤色不均，不仅写“普通女性”“无美颜”；发型、表情与视线按已选生活状态表达，不把人物比较过程或备选人设写进 prompt。面部不入镜时省略脸型、年龄与妆容。外貌特征替换空泛气质词，不累加五官描述。
- 将已确定的完整姿势写成可见的画面关系：身体与脸部朝向、视线、主要手臂的位置，以及必要的腿部、重心或环境支撑关系相互衔接。手接触商品时，写清接触位置、手相对身体的位置及商品最终状态；不能只用“轻轻”“稍微”或展示目的代替具体关系。只写本张有作用的关系，不用所有部位填满描述，也不为具体化而添加无依据的精确角度或距离。
- 商品使用形态集中表达，写清该姿势下相对身体的位置及必要的接触、受力或垂坠关系；不把正常折叠、弯曲或褶皱写成禁止变形。最终文本不写推理过程、动作许可清单或备选方案。
- 需要拍到腿部或完整下摆时，先确认拍法可行，不给一臂距离自拍硬塞全身范围；用镜头位置与可见关系说明画面，不靠“没有手 / 没有手机”等禁止项替代拍摄关系。
- 场景沿用主说明选定的普通日常环境，具体描述保持已选的装修、设施与陈设水平，不在组装时增加考究装饰、统一配色或升级场所档次。按 `realism-library.md` 将日常使用情况写成镜头内具体对象的位置、状态或活动，不能压缩为“日常背景”“有生活痕迹”，也不把环境内容当作独立道具清单。保留场景本来的美感，不用精致布置代替具体描述。
- 光线沿用方案中满足日常活动的照明条件，用简短文字说明光源与整体照明，不在组装时增加营造氛围的光源组合、色温对比或精细明暗设计。每份写入轻微但可见的白平衡偏差和细微噪点，现场条件决定其方向与强度；白平衡偏差不要求混合照明。其余成像表现按需表达，不覆盖已选姿势、视线或妆发。
- 成立性检查统一按主说明执行，发现问题先修正方案；最终 prompt 只包含本张所需的关系与约束，不转录检查过程或多样性比较要求。

## 最小记录格式

每份分别记录，多份共用商品条件时也要保留各自的完整 prompt 与交付状态，不能写“同第一份”。完成文本交付或生图后记录；第一节是**最终 prompt 全文**：已调用时保存实际传入工具的文本，仅提示词 / 等待确认时保存完整待执行文本，不能用摘要代替。后续用户确认后沿用该文本执行，按反馈有修改时先更新最终文本，再补充实际结果。其他内容简短即可，不另建 JSON 人物档案或历史去重索引。

````markdown
# <本次标识> · <商品简述>

## 一、最终 prompt
```text
<完整最终文本>
```

## 二、本次方案
- 商品条件：<目标、品类 / 部位、尺寸依据或未知、需保留的属性、可行使用变化>
- 拍摄方案：<拍照意图、人物与场景、商品使用状态、具体姿势、拍法与取景；只填本次相关信息>

## 三、参考图与结果
- REFERENCE_0：<商品图路径或可追溯标识；未调用时为计划输入，已调用时为实际输入>
- REFERENCE_1：<计划使用第二张图时填计划路径 / 标识；已调用时仅填写实际传入的第二张图，不使用则省略>
- 交付模式：<仅提示词 / 先预览 / 直接出图；预览获确认后注明已确认>
- 状态：<仅提示词 / 等待确认 / 已生成 / 生成失败 / 未生成及原因；仅提示词与等待确认不是失败>
- 图片：<成功时填同目录实际文件，如 ./001.png；归档失败时填实际来源并注明；未生成时不填写>
- 归档状态：<同目录保存完成 / 未完成及原因；未生成时注明仅保存 prompt>
- 图片来源：<仅在复制 / 下载或归档未完成时按需记录实际原路径或链接>
- 说明：<已生成时注明未执行自动视觉审核并请核对实物；仅提示词 / 等待确认时注明未调用生图及执行所需参考输入>
````

参考标识、调用状态与路径必须如实记录。图片与本记录的保存方式统一按主说明的同目录规则执行，成功时图片字段指向实际同目录文件，不能仅用外部来源代替；归档失败时图片字段只填写实际来源并注明失败，不填写拟保存但不存在的路径。档案只是方案记录，不代表人物一致性已建立；方案差异的比较统一按主说明执行。
