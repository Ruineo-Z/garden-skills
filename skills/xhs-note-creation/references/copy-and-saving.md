# 文案交付与保存

## 讨论阶段

方向未确定时先讨论 [三个方向](note-direction.md)，不提前写完整文案。方向确定后，默认给三个标题候选并简短推荐一个，同时按推荐标题给一版正文，方便一起判断。

正文用独立 `text` 代码块，保留分段和换行。候选、推荐理由与讨论说明放在代码块外。用户可以只改一个部分，不要求每步重新确认。

## 最终交付格式

用户确定标题和正文，或明确要求最终稿时，输出以下固定格式：

````markdown
标题
```text
<最终确定的标题>
```

正文
```text
<完整正文，保留实际发布时的分段和换行>
```
````

两个代码块各自只放可发布的文字，不包含字段名、引号包装、候选编号、推荐理由、创作说明、话题标签或自动追加的链接提醒。模板中的尖括号占位文字应替换为真实内容。

用户仅要标题或正文时只交付对应部分，仍使用同样的标签与独立代码块；不重写另一个部分。除非用户需要说明，不在最终稿周围追加解释或总结。未获确认的草稿不标成“用户已确认”。

## 保存在原笔记目录

沿用 [图片保存目录](prompt-and-saving.md#保存目录)，不在写文案当天另建一篇，不改动已存图片或提示词记录。用 `note.md` 保存该篇已确认主方向、所依据的图片、文案对标（如有）、当前状态，以及同样两个代码块中的完整标题正文。

- 方向讨论期间可只记录提案与选择状态；写出草稿后记录“待确认”，用户认可后记录“已确认”。
- 最终标题正文应与交付内容一致。没有文案对标时无需填写不存在的来源。
- 文案保存与图片的 `cover.md`、`1.md` 分开，不将笔记正文送进生图接口。
- 初稿使用 `note.md`；已有文案需修改时另存 `note-v2.md`、`note-v3.md` 等，保留旧稿。仍在同一版内补充讨论状态可更新该版，不覆盖其他笔记。
- 没有目录记录时，先从已有素材与上下文确认归属；用户只想临时获得文字时可以直接交付，不强制为单独润色创建笔记目录。
- 保存失败时如实说明，仍交付可复制内容，不声称文件已保存。文件路径或保存状态说明置于代码块外，仅在需要时告知。
