# 图片修改

## 默认方式

默认以目标原图为基础修改，保留用户已经认可的部分。只有用户明确要求重做、重新设计或换一套方案时，才重新推导整张图。

## 推导顺序

### 1. 理解反馈

确定目标图片和问题。用户说“姿势违和”“穿搭不合理”“背景不搭”时，先判断造成问题的具体关系，不要求用户逐个描述关节。

收到“平淡”“没氛围”“没有生命力”等反馈时，按 [共同摄影原则](../SKILL.md#用摄影思维推导画面) 判断光影、构图和人物状态哪里没有配合好，不默认用加逆光、放大人物或增加动作解决。将调整落实到修改后的可见状态。

### 2. 划分保留与调整

记录需要保留的内容，例如人物身份、背景、服装、商品、构图或画面质感；再确定要修改的部分。没有被反馈影响的内容不要顺手重做。

用户反馈人物“太 AI”时，区分身份与呈现方式：可以保持同一人物，调整皮肤、妆发、表情及现场光影，不把未被认可的精修质感列为必须保留，也不擅自换脸。具体调整以目标图中可见的问题为依据，不只添加“真人、毛孔、自然”等词。

### 3. 推导关联调整

修改一个局部时，检查它会影响的相邻关系：

- **手势或姿势**：一起检查衣袖、肩线、披肩接触、受力、褶皱、垂落、重心和取景。
- **穿搭**：一起检查披肩搭法、人物姿态、颜色关系和场景适配。
- **披肩状态**：一起检查手的位置、身体覆盖范围、垂落和材质形成的自然褶皱。
- **背景**：一起检查人物边缘、光线方向、阴影、脚下或座位接触，以及人物与空间的比例。
- **人物**：保持用户认可的商品、构图、背景和整体质感，除非反馈明确涉及这些内容。
- **封面**：修改后继续检查是否好看、抓眼球，并保留后续轻微动态的可能性。
- **后续配图**：修改后继续保持与封面的人物一致。

### 4. 检查修改方案

修改后的整张照片仍需满足：

- 调整后的光影、构图和人物状态相互协调，反馈对应的变化能在画面中体现；
- 现实中可以这样穿、这样摆、这样拍；
- 人物、服装、披肩、环境和机位相互成立；
- 商品外观没有被改款或臆造；
- 只修复反馈涉及的问题，没有无理由改变已满意内容。

## 最终修改提示词

修改提示词使用自然语言，不强行使用生成用 JSON。按以下顺序组织：

```text
以 REFERENCE_0 为基础。
保留：<用户认可且需要延续的内容>。
修改：<明确的问题和目标变化>。
关联调整：<因该修改必须同步调整的手势、衣袖、披肩、阴影、取景或环境关系>。
保持：<人物身份、商品结构、背景或构图中明确不变的内容>。
不要顺带改变：<与反馈无关的内容>。
```

如需商品图或封面参考，分别说明它们只负责商品外观或人物一致性，不让参考图之间的职责混淆。

## 返工边界

一次只处理用户指出的图片或问题。生成结果仍有问题时，说明具体问题，等待用户决定是否再次修改；不自动连续重出，也不把无关图片整批重做。
